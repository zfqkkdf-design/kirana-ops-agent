# Telegram-бот операцій крамниці

Бот однієї крамниці працює лише в Telegram. Залишок, ціну, GST і відмову продати більше, ніж є на полиці, рахує код. Мовна модель тільки обирає інструмент і передає власнику те, що цей інструмент повернув.

Запит про залишок іде в `check_stock`. Функція шукає товар у SQLite і повертає кількість, MRP і, якщо партій кілька, розбиття за порядком FEFO. Модель цю кількість не обчислює.

Продаж іде через інструменти рахунку. Якщо штук не вистачає, відмовляє код інструмента. Те саме з ціною, ставкою GST і борговою книгою khata: правило живе в `tools/`, а відповідь інструмента є джерелом факту. Системна інструкція каже прямо: кожен факт про товар, ціну, GST і залишок приходить з інструментів, нічого з цього не вигадувати.

Бот приймає фото товару. Штрихкод, якщо він читається, знімає zbar. Якщо коду немає, Gemini називає товар на знімку і переписує лише ті цифри штрихкода, які видно. Неповний код вона не домальовує. Далі назва потрапляє в той самий хід, що й набраний текст, а залишок знову читається з бази.

Голосове повідомлення транскрибується через Gemini і далі йде як текст замовлення. Розпізнавання фото і голосу завжди йде через Gemini, навіть коли основна модель у `LLM_PROVIDER` — Claude.

Рахунок, PDF-накладна, колода продажів, прихід нової партії, денне закриття, нагадування по khata і щотижневий звіт збирає код. Мова інтерфейсу, назва крамниці і GSTIN лежать у базі і не зникають після очищення історії чату командою `/newchat`.

## Стек

- Python 3.11+
- python-telegram-bot
- LangChain; модель Claude або Gemini, перемикач `LLM_PROVIDER`
- SQLite
- WeasyPrint для PDF-накладної, python-pptx для колоди продажів

## Запуск

Скопіюйте `.env.example` у `.env`, вкажіть токен бота і ключ обраної моделі.

```bash
pip install -r requirements.txt
python bot.py
```

Після `/start` бот пише, що рушій готовий. Далі власник текстом додає товар, збирає рахунок, просить денне закриття, PDF або колоду, а фото і голос потрапляють у той самий обліковий хід.
